Introduction

A few years ago, most open LLMs used the same attention design: grouped-query attention (GQA), in which multiple Query vectors attend to the same Key-Value vector to save memory. The optimization of attention did not stop there. Recent models use much more diverse attention mechanisms, and these mechanisms drastically change the HBM consumption, the memory loading, and the TFLOPs spent on the attention.

In this post, we look at eleven recent models: DeepSeek V4.1 Flash, DeepSeek V4 Pro, GLM-5.3-Flash, Qwen3.8 Flash Next, MiMo V2.6 Flash, Inkling, GLM-5.3, MiniMax-M3.1 Flash, Kimi K3, Kimi K3.1 Pro and Qwen3.8 27B. We compare them with Qwen3-Coder-480B-A35B, a GQA model of similar size to most of them.

At a 128K-token context, the new models need far less than the baseline:

  • Memory. A request keeps up to 139× less attention state (DeepSeek V4.1 Flash).
  • Decode. Each step loads up to 250× fewer bytes, and its attention runs up to 44× faster (DeepSeek V4.1 Flash).
  • Prefill. A prompt needs up to 183× fewer attention FLOPs (Qwen3.8 Flash Next), and its attention runs up to 46× faster (DeepSeek V4.1 Flash).

These changes matter beyond the numbers themselves. Much of today's performance analysis of LLM inference still rests on older GQA models: when a step is bound by attention and when by the FFN, how many requests fit in memory, and which kernels are worth tuning. The new attention designs change these answers.

Our main takeaway

The attention landscape has changed, and inference research needs to catch up.

New attention designs change how much memory a request needs, how many bytes each step moves, and how much it computes. As a result, the bottlenecks and optimization opportunities of GQA models do not always carry over. Future inference research should study these new models directly, instead of reusing conclusions drawn from GQA models.

Attention Variants

We first go through how each attention design works. They fall into two branches. The first keeps an entry for every earlier token in the cache. On this branch, GQA and MLA make each entry smaller, while sliding windows, DSA, CSA and HCA cut how much of the cache is kept or read. The second branch, linear attention, folds the whole context into a state of fixed size.

In standard multi-head attention, every query head has its own key head and value head. GQA lets a group of query heads share one key-value head, so each token keeps fewer keys and values. Our baseline, Qwen3-Coder-480B-A35B, has 96 query heads and 8 key-value heads in each layer, so 12 query heads share each key-value head.

The token's hidden state is first projected into queries, keys and values, and QK-norm and RoPE normalize the queries and keys and encode their positions. The keys and values are stored in the KV cache, where they stay for the entire lifecycle of the request. To compute its output, a new token compares its queries with the keys of all earlier tokens, turns these scores into weights with a softmax, and takes the weighted sum of the earlier tokens' values. The two blue arrows show these two reads from the cache: computing the scores reads every key, and the weighted sum reads every value.

MLA makes each entry smaller in a different way. Instead of storing keys and values per head, an MLA layer caches one compressed vector per token, the latent ckv, which all query heads share. Each head can rebuild its own key and value from ckv with two learned matrices, WUK and WUV.

In prefill, the engine rebuilds the keys and values of the earlier tokens from their cached latents with WUK and WUV (Expand K, V), and then computes attention as in GQA. The rebuild is paid once and shared by the thousands of tokens in the chunk.

In decode, only one new token arrives at each step, so rebuilding every earlier key and value just for it would be wasteful. Instead, the engine folds WUK into the new token's query (Absorb WUK) and applies WUV after the weighted sum (Absorb WUV). Attention then works on the cached latents directly, so both blue arrows start from the same cache row.

Absorbing WUK does not work if RoPE rotates the keys, because the rotation depends on each token's position. The original MLA in DeepSeek V2 therefore caches one more small key part per token, ks, which all heads share, and applies RoPE only to ks.

Kimi K3, whose layer the figure shows, changes MLA in two small ways. It drops RoPE, so ks is a plain key that carries no position. It also adds an output gate. A separate projection of the input gives a gate g, and before the output projection each number of the attention output is scaled by sigmoid(g).

A sliding-window layer attends only to the last W tokens. Older tokens are never read again, so the cache keeps only W entries and stops growing once the context passes the window. The window can sit on top of either GQA or MLA. MiMo V2.6 Flash uses GQA-based windows in most of its layers, and DeepSeek V4.1 Flash uses MLA-based windows in all of its layers. Both use W = 128.

In prefill, each token in the chunk compares its query only with the last W tokens up to itself, so the scores form a narrow band along the diagonal. In decode, each step adds the new token's entry and drops the oldest one.

Inkling also mixes window layers, with W = 512, and GQA layers. Instead of RoPE, it encodes positions with a learned bias that it adds to each score, based on how far apart the two tokens are. Its attention kernel must therefore compute this bias as well.

Not all earlier tokens matter equally. After the softmax, most of the weight usually falls on a few of them, and reading the rest barely changes the output. DSA, the sparse attention that DeepSeek introduced in V3.2, adds a small indexer in front of MLA to find these tokens. The indexer keeps its own short key, kI, for every token. For each new token, it scores every earlier token with a cheap dot product and keeps the 2,048 tokens with the highest scores. The layer then runs ordinary MLA over only these selected tokens.

The indexer still scores the whole context, but its key is small, so each score is cheap. Sparse attention therefore cuts what each step reads and computes, but not what a request stores: any token may be selected later, so every token stays in the cache.

In prefill, different tokens select different earlier tokens. Expanding the whole context would rebuild keys and values that most tokens never read, so vLLM keeps long Kimi K3.1 Pro prompts on the absorbed path in prefill too.

GLM-5.3 and GLM-5.3-Flash also use DSA, each with one change to the indexer. In GLM-5.3, only some layers run an indexer, and the others reuse the most recent selection. GLM-5.3-Flash keeps one index key for every 4 tokens and selects tokens in groups of 4.

DeepSeek V4 introduced CSA, which combines the ideas above. The most recent 128 tokens are kept in a window, as in SWA. Older tokens are compressed: a learned compressor merges a few consecutive tokens into one entry, 4 tokens in DeepSeek V4 Pro. An indexer, as in DSA, then selects some of these entries, 1,024 in DeepSeek V4 Pro, and attention reads only the window and the selected entries. Unlike MLA, the cached vector itself serves as the key and the value of every head, with no WUK or WUV.

DeepSeek V4 Pro pairs CSA with heavily compressed attention (HCA) and alternates the two across its layers. An HCA layer merges every 128 tokens into one entry, so its compressed cache is small enough to read in full. It therefore needs no indexer: attention reads the window and every compressed entry.

DeepSeek V4.1 Flash uses a revised version, which we call CSA2. It compresses less: layers in the first half merge every 2 tokens, and layers in the second half do not compress at all. To save memory, it stores the entries in FP4 and lets several layers share one cache and one selection. Only 4 of the 40 layers write a compressed cache, and the other layers read the cache of the nearest writer before them. The indexer runs in 8 layers: the 4 writers, and 4 more in the second half that select again from layer 20's cache. Every other layer reuses the selection of the nearest indexer layer before it. The figure follows layer 2, the first writer. Layers 3 to 7 read its cache and reuse its selection.

Layer 20 writes the cache that all later layers read, so layers 21 to 39 write no compressed cache. In prefill, these layers therefore only need to run over the last 128 tokens of the prompt, enough to fill their SWA windows. DeepSeek calls this SWA bounded replay, and vLLM (PR #58132) and SGLang implement it.

A linear-attention layer keeps no entry per token. Instead, each head keeps one matrix S of fixed size, with one row per key channel and one column per value channel. A token writes into S by adding the product k v⊤ of its key and value, and reads its output as o = S⊤ q. Because every token adds to the same matrix, the state never grows. But it also never forgets, so over a long context the stored values pile up and blur into each other.

Gated DeltaNet (GDN), used by Qwen3.8 Flash Next and Qwen3.8 27B, fixes this in two ways, and each gives it part of its name. The first is the delta rule. Before writing, the token reads what S already stores for its key, S⊤ k, and writes only the difference from its own value v. With a write strength β between 0 and 1, the update is S ← S + β k (v - S⊤ k)⊤. A key that is written again therefore replaces its old value instead of adding to it. The second is the gate. Before each write, S is multiplied by a decay α between 0 and 1, so content that is not written again fades over time. In GDN, α is one number per head, so the whole state of a head fades at one rate.

Kimi Delta Attention (KDA), used by GLM-5.3-Flash, Kimi K3 and Kimi K3.1 Pro, keeps the delta rule but makes the gate finer. Its α holds one decay per key channel, so each row of S fades at its own rate: some rows keep old content for long, while others forget quickly. The figure shows a KDA layer. Its Gates step turns each token into the input of the decay α and into an output gate g. The attention kernel then computes α and applies the delta rule, and g scales the attention output before the output projection, as in Kimi K3's MLA layer.

In decode, each step reads and writes the same state at any context length. In prefill, running the update token by token would leave the GPU idle. The kernel therefore splits the prompt into chunks of 64 tokens, computes each chunk with matrix multiplies, and passes S from chunk to chunk. A state of fixed size cannot keep every detail of a long context, so these models keep a few full-attention, DSA or QSA layers to look back exactly.

Takeaway. Each variant in one line:

  • GQA: several query heads share one key-value head.
  • MLA: each token's keys and values are compressed into one latent vector.
  • SWA: the layer keeps only the last W tokens.
  • DSA: an indexer selects the top-k tokens, and MLA runs over only those.
  • MSA: an indexer selects the top-k blocks of tokens, and GQA runs over only those.
  • QSA: like MSA, with much smaller blocks, so the selection is finer.
  • CSA: the keys of several tokens merge into one entry, and DSA runs over these entries.
  • HCA: many more tokens merge into one entry, so attention reads all entries without an indexer.
  • CSA2: a few layers write the compressed keys, and the other layers share them.
  • GDN: every token updates a fixed-size state whose old content keeps fading.
  • KDA: GDN in which each channel of the state fades at its own rate.

At 128K tokens, the baseline, MiMo V2.6 Flash, Qwen3.8 27B, Kimi K3, GLM-5.3 and DeepSeek V4 Pro all reach 1.3 to 1.8 PFLOP/s on one B200, so their prefill time roughly follows their FLOPs. GLM-5.3 spends more than a third of its attention time on the indexer and the top-k selection. At 1M tokens, these two take most of the attention time in every model with an indexer, except Qwen3.8 Flash Next.

The other new models run their attention more slowly, so their time falls by much less than their FLOPs. Qwen3.8 Flash Next needs 183 times fewer FLOPs than the baseline but is only 13 times faster. Most of that time goes to its sparse attention, which reaches only about 90 TFLOP/s. Kimi K3.1 Pro's attention reaches only about 640 TFLOP/s, because vLLM runs its sparse MLA prefill in BF16 and pads its 96 heads to 128. Inkling needs about as many attention FLOPs as MiMo V2.6 Flash, but its attention takes 1.8 times as long and reaches about 1.0 PFLOP/s. Both models run FlashAttention 4, but Inkling's version also adds a learned position bias to every score, which may account for part of the gap.

Conclusion and Get Started

Attention in open models is no longer one design. At 128K tokens, the eleven new models keep 1.8× to 139× less attention memory than a GQA model of similar size, and they read and compute far less in decode and prefill. The time saved is smaller than the work saved, because the new designs add work, such as indexers, and some of their kernels run far below the GPU's peak. Inference analysis and optimization should start from these models.

The kernel times in this post come from ServingStudio Sim's measured kernel profiles. ServingStudio Sim also models whole serving steps, beyond attention. On the Models page, you can explore models such as Inkling, DeepSeek V4 Flash, GLM-5.2 and Qwen3-235B. For each one, the page shows its attention layout and cache parts, the cost tree that builds one step's time from measured kernels, and a live prediction for a batch of your own. The simulator is on GitHub.
